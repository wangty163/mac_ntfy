# 🔔 Ntfy for Mac · 使用说明与注意事项

Ntfy for Mac 是一个原生 macOS 菜单栏客户端，用来订阅 [ntfy](https://ntfy.sh)
主题（topic）并接收原生系统通知。它常驻菜单栏、后台保持长连接、断线自动重连，
适合作为服务器告警、CI/CD、家庭自动化等场景的实时推送接收端。

本文档按「**先把它跑起来 → 再了解高级用法 → 最后看注意事项**」的顺序组织，
带 ⭐ 的是核心步骤/必读项，其余为按需了解的进阶内容。

---

## 一、快速上手（核心流程）⭐

只需四步即可收到第一条通知。

### 1. 安装与首次启动 ⭐

1. 下载并打开 `NtfyMac.dmg`，把 **Ntfy for Mac** 拖入「应用程序」。
2. 首次启动时，由于安装包**未签名**，macOS Gatekeeper 会拦截：
   **右键（或 Control + 单击）应用图标 → 打开 → 再次点击「打开」**。
   此操作只需做一次，之后即可正常双击启动。
3. 启动后图标出现在**菜单栏**（不在 Dock 里）。系统会弹出**通知授权**请求，
   请点击「允许」——否则收不到任何横幅通知。

### 2. 添加一个订阅 ⭐

1. 点击菜单栏的 🔔 图标 → **Open Ntfy** 打开主窗口。
2. 点击 **Add Subscription**，填写：
   - **Server URL**：ntfy 服务器地址，默认 `https://ntfy.sh`，自建服务器填自己的地址。
   - **Topic**：主题名，相当于一个「频道」。任意人知道这个名字即可向它发消息，
     公共服务器上请使用**不易被猜到**的名字（详见注意事项）。
   - **Display Name**（可选）：在 App 内显示的别名。
3. 点击 **Test** 验证服务器与鉴权是否可达，显示「Connection OK」后再点 **Subscribe**。

### 3. 验证能收到通知 ⭐

订阅成功后，给自己发一条测试消息：

```bash
curl -d "Hello from ntfy 👋" ntfy.sh/<你的-topic>
```

或直接用 App 内的 **Publish**（纸飞机图标）发送。几秒内应收到原生系统通知，
并出现在菜单栏面板和主窗口的消息列表中。

### 4. 设为开机自启（推荐）

打开 **Settings → General**，开启 **Launch at login**，让它随系统启动并常驻后台。
配合关闭 **Show window at launch**，可实现「开机后静默驻留菜单栏」。

## 二、日常使用

### 菜单栏面板
单击菜单栏 🔔 图标弹出紧凑面板：

- 顶部显示连接状态（如 `2/3 topics connected`）与未读数。
- 中部列出**未读消息**，点击某条会标为已读并在主窗口中定位到它。
- 底部按钮：**Open Ntfy**（主窗口）、✓（全部标为已读）、⚙️（设置）、⏻（退出）。

### 主窗口
- 左侧边栏管理订阅：添加、编辑、删除、查看每个主题的连接状态。
- 右侧消息列表支持**搜索**、已读/未读、静音（mute）。
- 点击单条消息查看详情，包括 Markdown 正文、标签、附件预览与操作按钮。

### 发送消息（Publish）
在订阅上点击 **Publish**（纸飞机图标）可直接从 App 发消息，支持：
标题、优先级（1–5）、标签、点击跳转 URL、**定时发送**（如 `30min`、`9am`）、
附件 URL、以及 Markdown 正文。

## 三、进阶功能

### 鉴权（受保护的主题）
添加/编辑订阅时可选择鉴权方式：
- **None**：公共、无保护的主题。
- **Username**：Basic Auth（用户名 + 密码）。
- **Token**：访问令牌（`tk_…`）。

### 按优先级 / 标签过滤
- **全局**：`Settings → Notifications → Minimum priority to alert` 设定最低提醒优先级，
  低于该优先级的消息**仍会存入历史**，只是不弹横幅。
- **按主题**：在订阅的 **Filters** 中指定只对某些优先级、或包含特定标签的消息提醒。

### 通知样式
- ntfy **优先级 1–5** 会映射到 macOS 的中断级别与提示音。
- **标签自动转 emoji**（如 `warning` → ⚠️、`rotating_light` → 🚨）。
- 支持**点击动作**（打开 URL）、**附件**（图片内联预览 + 下载）、
  **操作按钮**（`view`、`http`；`broadcast` 仅 Android 可用）。

### 设置项一览（Settings）
- **General**：默认服务器、开机自启、启动时是否显示窗口、菜单栏未读角标、
  代理模式、每个主题的历史条数上限（20–2000）、清空历史。
- **Notifications**：通知权限状态、是否显示系统通知、是否播放声音、最低提醒优先级。
- **About**：版本信息与 ntfy 文档链接。

## 四、注意事项 ⚠️

### 🔴 重要（务必了解）

1. **必须授予通知权限。**
   未授权时 macOS 不会显示任何横幅。可在
   `Settings → Notifications` 查看状态，或点「Open Settings」前往系统设置开启。
   若系统设置里**根本找不到本应用**，通常是因为安装的是未签名构建——请改装签名版。

2. **未签名构建首次启动会被拦截。**
   见快速上手第 1 步，用「右键 → 打开」放行一次即可。

3. **系统代理（Clash / Surge 等）会导致主题掉线。**
   当代理工具开启 macOS **系统代理**时，长连接通知流可能被缓冲/卡死，且本地
   `/etc/hosts` 覆盖会失效——即使为 ntfy 服务器配置了 DIRECT 规则也无效，
   因为连接仍会先进入代理。解决方式在 `Settings → General → Proxy` 中显式选择：
   - **Direct（忽略系统代理）**：默认且推荐，开着系统代理时也直连服务器。
   - **System proxy**：跟随系统代理（仅在确实可用的环境下使用）。
   - **Custom proxy**：把全部 ntfy 流量走指定的 HTTP(CONNECT)/SOCKS5 代理，
     需选择**支持流式传输**的端口（如 Clash 的 mixed/SOCKS 端口）。

4. **公共服务器上的主题名 = 密码。**
   `ntfy.sh` 是公开的，任何知道主题名的人都能收发该主题的消息。请使用
   **足够随机、不易被猜到**的主题名，敏感场景请自建服务器并启用鉴权。

5. **它依赖后台常驻。** 退出 App（菜单栏 ⏻）后将停止接收通知。
   建议开启 **Launch at login** 保持常驻。

### 🟡 次要（特定场景再看）

6. **浏览器能打开、App 却报「网络连接已断开」。**
   多见于通过 `/etc/hosts`、VPN、split-DNS 才能访问的自建/反代服务器。
   本应用**先按主机名连接**，仅当其失败时才回退到 `/etc/hosts` 中的 IP。直接拨裸 IP 会
   保留 `Host` 头但**丢失 TLS SNI**（IP 不能放进 SNI），反向代理可能因此选错证书或后端、
   把 HTTPS 请求路由到错误的地方；按主机名连接能保持 SNI 正确，所以始终优先尝试。回退拨 IP
   时仍保留原始 `Host` 头以便反代正确路由；服务器 URL 请填**主机名**而非裸 IP。

7. **域名没变、但服务器 IP 变了（动态 DNS / 故障切换 / 更新了 `/etc/hosts`）后，App 连不上、浏览器却正常。**
   恢复方式和浏览器一样：**按主机名连接**。浏览器和 App 都走系统解析器，而系统解析器会优先读
   `/etc/hosts`，所以把该条目改成新 IP 后，重连即可自动生效。服务器 URL 请保持填**主机名**（含非标准
   端口，如 `https://ntfy.example.com:8443`），不要填裸 IP。
   为什么 HTTPS 不直接由 App 自己拨 IP：连裸 IP 虽保留 `Host` 头，但无法把主机名作为 TLS **SNI**
   发送（IP 不允许出现在 SNI 中）。反向代理若按 SNI 选证书/后端，就会路由到错误的 vhost——短请求可能仍
   返回 2xx，但长连接订阅流会被路由错而断开。因此 HTTPS 始终按主机名连接；只有纯 **HTTP**（无 TLS/SNI）
   才会在失败后回退到 `getaddrinfo` 解析出的 IP。
   若 App 长时间运行、改了 `/etc/hosts` 后仍卡在旧 IP，退出重开（或编辑一下订阅触发重连）即可让新连接重新解析。

8. **长时间离线后可能因 `since` 游标过期而拉不到消息。**
   ntfy 只缓存有限时间的历史消息，本应用会在保存的游标被服务器拒绝时自动清除并重连，
   一般无需手动干预。

9. **历史是有上限的。** 每个主题默认保留有限条数（可在 `Settings → General` 调整，
   20–2000），超出会被裁剪。

10. **`broadcast` 操作按钮仅 Android 可用**，在 macOS 上不会生效。

11. **数据均存储在本地** `~/Library/Application Support/NtfyMac/`，
    应用只会与你配置的 ntfy 服务器通信，不上传任何数据到第三方。
